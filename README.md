# 나라장터 「협상에 의한 계약」 공고 추출

나라장터 입찰공고 중 **낙찰자결정방법이 "협상에 의한 계약"인 공고**만 골라내, 지일이 검토할 만한 순서로 정리하는 시스템입니다.

기존 주간 이메일 시스템(`narajangter-bid-monitor`)과는 **별개로 동작합니다.** 그쪽 코드는 건드리지 않습니다.

---

## 왜 "낙찰자결정방법"인가

「협상에 의한 계약」은 계약체결방법이 아니라 **낙찰자결정방법**입니다.

| 필드 | 값 | 역할 |
|---|---|---|
| `sucsfbidMthdNm` (낙찰자결정방법) | `협상에의한계약-…` | **여기로 판별합니다** |
| `cntrctCnclsMthdNm` (계약체결방법) | 일반경쟁 / 제한경쟁 / 수의계약 | 협상과 **직교**합니다. 필터축이 아닙니다 |

협상 공고는 일반경쟁·제한경쟁 양쪽에 걸쳐 있어서, "계약방법 = 제한경쟁"으로 거르면 일반경쟁 쪽을 통째로 놓칩니다.

접미 괄호 변형이 여러 개라 **접두어 매칭**을 씁니다.

```
협상에의한계약-협상에 의한 낙찰자 결정
협상에의한계약-협상에 의한 낙찰자 결정(SW사업)
협상에의한계약-협상에 의한 낙찰자 결정(건설엔지니어링)
협상에의한계약-협상에 의한 낙찰자 결정(엔지니어링)
```

## 처리 흐름

```
① 수집        업무구분 3종(용역·물품·공사) 일 1회 증분
                  ↓  원문(raw) 그대로 저장 — 담당자 연락처만 제거
② 스코프      최신 차수 → 취소공고 제외 → 협상만 남김
                  ↓        (설계공모·규격가격동시입찰은 '인접'으로 분리 보관)
③ 업역        해외 전시회 한국관/단체관 설치 제외 / 키워드 / 제외키워드 / 최소예산 / 품명·업종코드
                  ↓        ※ 해외공고 제외는 신규 방침(국내만 취급), 나머지는 기존 시스템과 동일한 규칙
④ 자격 게이트  면허제한정보 대조
                  ↓        ※ 기존 시스템과 동일한 규칙 (미충족 2그룹 이상이면 제외)
                  ↓        API가 비어 fail-open 통과한 최종 후보는, 첨부파일 "입찰참가자격"
                  ↓        절의 업종코드/세부품명번호를 보유 목록과 대조해 자동으로 다시
                  ↓        판정한다(코드가 있는 항목만; 게이트 자체를 다시 태우진 않음)
                  ↓        재공고는 새 공고번호를 받아 차수 정리로 안 묶이므로, 발주기관+
                  ↓        제목 유사도로 같은 사업을 찾아 가장 최근 공고만 남긴다
                  ↓        (`scope.group_projects` — 예산 일치만으로는 묶지 않는다)
⑤ 정보 부착    공동수급 · 마감 3종 · 재공고 · 참가가능지역
                  ↓        ※ 판정에 개입하지 않고 정보로만
⑥ 리포트      마감 임박 순 → 강력추천 순. 콘솔 / CSV / HTML
```

**②의 순서가 중요합니다.** 최신 차수를 먼저 고르고 취소 여부를 봅니다. 반대로 하면 "000 등록 → 001 취소"인 사업에서 000이 살아남아 취소된 사업이 검토 목록에 올라옵니다.

## 기존 시스템에서 그대로 가져온 것

다시 만들지 마세요. 전부 실제로 겪은 문제에 대한 대응입니다.

- **비표준 오류 응답 대응** — 오류가 `{"nkoneps.com.response.ResponseError": …}` 형태로 오는 경우가 있어, 응답 트리를 재귀 탐색해 `resultCode`를 찾습니다. 고정 경로만 보면 실제 오류코드를 놓치고 99로 덮어씁니다.
- **items 형태 5종 정규화** — 배열 / 단일 객체 / `{item: [...]}` / `{item: {...}}` / 빈 문자열로 제각각 옵니다.
- **JSON/XML 양쪽 파싱** — `type=json`을 요청해도 인증 오류에서는 XML이 돌아옵니다.
- **면허제한정보 기간 일괄 조회** — 이 API는 `bidNtceNo`를 넘겨도 서버가 필터링하지 않고 조회기간 전체를 내려줍니다. 그래서 공고별로 호출하지 않고 **기간 전체를 1회 받아 로컬에서 공고번호별로 묶습니다.** 공고 수가 늘어도 API 호출 횟수가 늘지 않습니다.
- **부분 실패 허용** — 업무구분 하나가 실패해도 나머지로 진행하고, 리포트에 경고를 답니다. 3종 전부 실패하면 "0건"이 아니라 오류로 끝냅니다. 장애를 "해당 없음"으로 오인하면 안 되기 때문입니다.
- **보유 자격 목록** — `config/held_qualifications.json`은 기존 레포에서 복사한 것입니다. 등록증이 갱신되면 **양쪽 다** 고쳐야 합니다.

## 판정 규칙은 바꾸지 않습니다

자격조건·키워드·예산 규칙은 **기존 시스템과 동일**합니다. 회사가 정한 사업 판단이라 임의로 바꾸지 않습니다.

- 제한그룹(`lmtGrpNo`) 하나가 자격조건 하나의 단위, 그룹 안에서는 하나만 보유해도 충족(OR)
- 충족 못한 그룹이 **2개 이상이면 제외** (1개까지 통과) — `MAX_ALLOWED_MISSING_QUALIFICATIONS`
- 자격정보가 없거나 조회 실패면 **걸러내지 않고 통과**(fail-open)
- 제외키워드가 제목에 있으면 무조건 제외 / 예산 미상은 통과 / 업종코드 단독 매칭은 결과에서 제외

업종명은 기존과 같이 **양방향 부분일치**로 대조합니다. 그래서 `건축공사업`이 보유 업종 `실내건축공사업`의 부분 문자열이라 충족으로 판정되는 경우가 있습니다. 현행 동작이며, `tests/test_pipeline.py`의 `test_substring_matching_is_permissive`에 성질만 기록해 뒀습니다.

## 설치 · 실행

```bash
pip install -r requirements.txt

# API 키 없이 동작 확인 (픽스처로 전 구간 실행)
python scripts/demo.py

# 테스트
python -m unittest discover -s tests -t .

# 실제 수집 (인증키 필요)
export NARA_SERVICE_KEY="발급받은 인증키(Decoding/평문)"
python -m nego                 # 최근 1일치
python -m nego --days 30       # 기간 지정

# 저장된 원문으로 재필터링 (API 호출 없음 — 키워드 바꿔보며 비교할 때)
python -m nego --from-store

# 응답 필드명 진단 (리포트 값이 비어 보일 때)
python -m nego --verify
```

> 인증키는 반드시 **"일반 인증키(Decoding / 평문)"** 값을 넣으세요. Encoding 키를 넣으면 URL 인코딩이 중복 적용돼 인증 오류가 납니다.

## 출력

```
[ 1] ○○과학관 전시물 제작 및 설치
     D-6 (자격등록 마감)  ·  ○○광역시  ·  5.0억
     강력추천  ·  공동수급: 공동이행 또는 분담이행  ·  자격 충족 (1개 그룹 전부)
     재공고
```

**정렬 기준은 마감 임박 순이 먼저입니다.** 아무리 좋은 공고여도 D-3이면 제안서를 쓸 수 없기 때문입니다.

리포트에 붙는 정보와 그 이유:

| 항목 | 왜 필요한가 |
|---|---|
| 실질 마감 (D-day) | 자격등록·공동수급협정·입찰 **세 마감 중 가장 이른 것**. 입찰마감만 보다가 자격등록을 놓치면 그대로 실격입니다 |
| 공동수급 | 불허면 단독으로만 가능합니다. `(제출방식)이행방식` 구조를 분해해 표시합니다 |
| 재공고 | 직전 회차 유찰 = 경쟁이 적다는 신호입니다 |
| 직찰(비전자) | 방문·우편 접수라 전자입찰 일정 필드가 비어 있는 게 정상입니다 |
| 첨부파일 수 | 다음 단계(첨부 파싱)의 입력입니다. 목록은 지금부터 저장해 둡니다 |

## 저장

두 군데에 저장합니다.

| 저장소 | 내용 | 언제 |
|---|---|---|
| **Supabase** `협상에의한계약 추출 로직_1차` | 협상 공고 (후보 + 제외된 것 모두) | `SUPABASE_URL`·`SUPABASE_SERVICE_ROLE_KEY`가 있을 때 |
| 로컬 JSONL `data/notices.jsonl` | 수집한 전체 공고 원문 | 항상 (GitHub Actions에서는 실행 후 사라집니다) |

GitHub Actions는 실행이 끝나면 파일시스템이 날아가므로, **실질적인 저장소는 Supabase입니다.**

### 왜 제외된 공고까지 저장하는가

`is_candidate = false` 로 같이 넣습니다. 나중에 **"이 공고가 왜 안 떴지?"** 를 확인할 수 있어야 하기 때문입니다. 제외 사유는 `qualification_summary`에 `제외: 제외키워드 (유지보수)` 같은 형태로 들어갑니다.

```sql
-- 오늘 후보
select title, days_left, earliest_deadline_kind, joint_exec_type
from "협상에의한계약 추출 로직_1차"
where is_candidate = true
order by earliest_deadline;

-- 왜 걸러졌는지 확인
select title, qualification_summary
from "협상에의한계약 추출 로직_1차"
where is_candidate = false;
```

같은 공고(업무구분 + 공고번호 + 차수)는 **UNIQUE 제약으로 한 행만** 유지되고, 다시 수집하면 UPDATE 됩니다(`updated_at` 자동 갱신). 매일 돌려도 행이 중복되지 않습니다.

**원문(raw)을 `jsonb` 컬럼에 통째로 보관합니다.** 나중에 첨부 파싱·배점표 추출을 붙일 때 재수집 없이 이 컬럼만 다시 읽으면 됩니다.

저장 실패는 실행을 중단시키지 않습니다 — 리포트는 이미 만들어졌고, 다음 실행에서 같은 공고를 upsert하면 복구됩니다.

담당자 이름·전화·이메일은 **저장 전에 제거**합니다(`fields.PERSONAL_FIELDS`). `data/`와 `output/`은 `.gitignore`에 있고, GitHub Actions도 `output/`만 아티팩트로 올립니다.

**이 레포는 비공개여야 합니다.**

## 아직 안 한 것

- **실적요건·신용평가등급 자동 판정** — 첨부파일 다운로드·텍스트 추출·등록업종(업종코드/세부품명번호) 자동 판정까지는 구현했지만(면허제한정보 API가 비어 있는 최종 후보 대상, `nego/qualify.evaluate_from_text_items`), 실적(기간·발주처·금액 등 다차원 조건)과 신용평가등급은 아직 코드로 표현되지 않는 요건이라 자동 판정하지 못합니다 — 절을 찾아도 판정 못 하면 원문 요약만 남기고 사람이 확인해야 합니다. (지역제한은 전국 대상 수집 방침에 따라 필터링 대상에서 제외하기로 함 — 참가가능지역 API 값은 계속 정보로만 표시)
- **배점표 추출 / 싱크로율** — 제안서 확인 후 진행하기로 했습니다.
- **실무자 피드백 수집**
